Step transitions use AnimatePresence x-axis crossfade.

   **D-15 (updated) handoff pattern:** On confirm, the dialog (1) kicks off a fire-and-forget POST to `/api/generate-story` (does not await the streamed response body), (2) calls `router.refresh()` once to pick up the server's `generation_status='generating'` write (the route sets this synchronously before opening the stream — Plan 03-03 Task 1 step 6), (3) IMMEDIATELY closes the dialog. The page's `GeneratingStoryState` component (Plan 03-04 Task 2/3) then renders the full `GenerationProgress` inline. When the regeneration completes server-side (~15-60s), the 4s `router.refresh()` poll in GeneratingStoryState picks it up and the page swaps to StorySection.

   **Pre-flight error path:** If the fetch fails synchronously (e.g. `!response.ok` returned before the stream opens — auth lost, invalid trip), the dialog stays open at Step B with an inline error + Try again CTA. This only catches errors that happen BEFORE the route sets `generation_status='generating'` (because once the status is set, the page UI takes over).

The plan ends with a **mandatory human-verify checkpoint** that exercises the full Phase 3 success criteria (4 from ROADMAP §Phase 3) end-to-end.
