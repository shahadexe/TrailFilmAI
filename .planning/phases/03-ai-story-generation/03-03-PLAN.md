<objective>
Wire the Gemini library (Plan 03-01) and the extended store (Plan 03-02) into:

1. A new Edge Runtime API route at `POST /api/generate-story` that performs the full generation lifecycle: auth → ownership → set `generation_status='generating'` → fetch photos → call `generateStory()` with 1 retry (D-05) → on success: delete-then-insert `story_chapters` + update `trips.story_tone` + `generation_status='completed'` → on failure: set `generation_status='failed'` → stream JSON result then close.
2. A new Wizard Step 3 surface (ToneSelector + ToneStep + GenerationProgress) that lets the user pick a tone, click "Generate your story", see rotating status text + amber CSS progress bar, and on success navigate to `/trip/[id]`, or on failure see an inline error + "Try again" CTA (D-05).
3. TripWizard's third branch in the AnimatePresence + D-11 resume support (read `?tripId=&resume=3` from `/new` search params, hydrate the Zustand store on mount).

Purpose: This is the heart of Phase 3 — it implements STORY-01, STORY-02, and STORY-03 end-to-end for the new-trip wizard path. After this plan ships, a user can create a trip → upload photos → pick a tone → generate a story → land on `/trip/[id]` (which Plan 03-04 will then extend to render the chapter list).

Output: 4 new files (route, ToneSelector, ToneStep, GenerationProgress) and 2 modified files (TripWizard, /new page). No regeneration UI yet (Plan 03-05); no chapter list rendering yet (Plan 03-04).
