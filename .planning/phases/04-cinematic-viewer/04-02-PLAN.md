    Create `src/components/viewer/ViewerMap.tsx` as a `'use client'` component.

    Imports (in order): `useEffect`, `useRef` from react; default `mapboxgl` from `mapbox-gl`; side-effect `import 'mapbox-gl/dist/mapbox-gl.css'`; named `NoGpsState` from `@/components/viewer/NoGpsState`.

    Type declarations (exported alongside the component):
    - `export interface ChapterCoord { chapterIndex: number; lat: number; lng: number; label?: string }`
    - `interface ViewerMapProps { chapterCoords: ChapterCoord[]; activeChapterIndex?: number }`

    Default export: named function `ViewerMap({ chapterCoords, activeChapterIndex }: ViewerMapProps)`.

    Refs: `const mapContainer = useRef<HTMLDivElement>(null)` and `const map = useRef<mapboxgl.Map | null>(null)`.

    First useEffect — map init (dependency array `[]` — init once on mount; chapterCoords changes are handled by the second useEffect, which is the architecturally simplest split for Mapbox):
    - Guard: `if (!mapContainer.current || map.current) return`
    - Create the map: `map.current = new mapboxgl.Map({ container: mapContainer.current, style: 'mapbox://styles/mapbox/dark-v11', center: [chapterCoords[0]?.lng ?? 0, chapterCoords[0]?.lat ?? 0], zoom: 8, interactive: true })`
    - Cleanup: return `() => { map.current?.remove(); map.current = null }`

    Second useEffect — markers + path (dependency `[chapterCoords]`):
    - Guard: `if (!map.current || chapterCoords.length === 0) return` (NoGpsState renders separately when empty)
    - Wait for the map style to be ready: use `map.current.on('load', () => { ... })` if the map is not yet loaded, or call directly if already loaded. Simplest pattern: hold a ref or local boolean `isLoaded` initialized from the first useEffect's `map.current.on('load', ...)` callback, OR check `map.current.isStyleLoaded()` and either run immediately or listen for `style.load` once.
    - Inside the loaded callback:
      - Add markers: for each `coord` in `chapterCoords`, create `const el = document.createElement('div')` and set `el.style.cssText = 'width:8px;height:8px;border-radius:50%;background:#E5A663;'`, then `new mapboxgl.Marker(el).setLngLat([coord.lng, coord.lat]).addTo(map.current!)`. Track the created marker instances in a local array so they can be removed on cleanup.
      - If `chapterCoords.length > 1`: add the path source as a GeoJSON LineString with coordinates `chapterCoords.map((c) => [c.lng, c.lat])`. Add the line layer with paint `{ 'line-color': '#E5A663', 'line-width': 2, 'line-opacity': 0.8, 'line-dasharray': [2, 2] }` (dashed per D-05 decision — resolved in UI-SPEC §Claude's Discretion Resolutions; do not change to solid). Layout: `{ 'line-join': 'round', 'line-cap': 'round' }`.
    - Cleanup: remove the markers and (if added) remove the `route` layer + source so the next chapterCoords change can re-add them cleanly.

    Third useEffect — activeChapterIndex flyTo (dependency `[activeChapterIndex, chapterCoords]`):
    - Guard: `if (activeChapterIndex === undefined || !map.current) return`
    - Look up the active coord: `const coord = chapterCoords.find((c) => c.chapterIndex === activeChapterIndex)`. If not found, return.
    - Call `map.current.flyTo({ center: [coord.lng, coord.lat], zoom: 10, duration: 1500, essential: true })`. `essential: true` is mandatory — UI-SPEC explicitly states map flyTo is spatial navigation and is NOT gated on useReducedMotion.

    Container JSX — responsive sidebar/bottom-sheet:
    Per UI-SPEC, the desktop sidebar and mobile bottom sheet are mutually exclusive layouts. The PATTERNS.md analog notes that both fixed-position states cannot apply to the same element. Implementation: render TWO sibling div elements — one for desktop sidebar (visible only on `md:` and up) and one for mobile bottom sheet (visible only below `md:`), each with its own `mapContainer` ref target. The simplest approach that keeps ONE Mapbox instance: render one outer wrapper that holds the map, and use a Tailwind responsive class string that resolves to one layout per breakpoint. Use the cleaner approach: a single `<div ref={mapContainer} className="w-full h-full" />` nested inside an outer `<div>` whose Tailwind classes apply different `fixed` positions based on viewport.

    Concretely, render:
    ```
    Outer wrapper #1 (desktop sidebar): className="hidden md:block fixed right-0 top-0 w-[38vw] h-[100dvh] z-20 border-l border-[rgba(255,255,255,0.06)] bg-ink" role="region" aria-label="Trip route map" tabIndex={0}
    Outer wrapper #2 (mobile bottom sheet): className="md:hidden fixed bottom-0 left-0 right-0 h-[40dvh] z-20 border-t border-[rgba(255,255,255,0.06)] bg-ink/90 backdrop-blur-xl" role="region" aria-label="Trip route map" tabIndex={0}
    ```
    Each wrapper contains its own inner `<div className="relative w-full h-full"><div ref={...} className="w-full h-full" />{chapterCoords.length === 0 && <NoGpsState />}</div>`.

    However, dual containers means two Mapbox instances would mount. The correct implementation: render ONE wrapper that uses Tailwind responsive classes to switch position at the breakpoint, e.g. a single container with both desktop and mobile classes layered such that only one set applies per breakpoint. Example: `className="fixed z-20 bg-ink right-0 top-0 hidden md:block w-[38vw] h-[100dvh] border-l border-[rgba(255,255,255,0.06)]"` — but this hides the map on mobile.

    Resolution: use one outer wrapper whose position classes change responsively WITHOUT `hidden`/`block` toggles. Use Tailwind responsive overrides on `fixed` positioning props:
    - Mobile (base): `fixed bottom-0 left-0 right-0 h-[40dvh] border-t border-[rgba(255,255,255,0.06)] bg-ink/90 backdrop-blur-xl`
    - Desktop (md:): `md:top-0 md:left-auto md:right-0 md:bottom-auto md:h-[100dvh] md:w-[38vw] md:border-t-0 md:border-l md:border-[rgba(255,255,255,0.06)] md:bg-ink md:backdrop-blur-none`

    Apply both class sets to ONE wrapper. ONE inner `<div ref={mapContainer} className="absolute inset-0" />` is the map root. Add the NoGpsState as a sibling: `{chapterCoords.length === 0 && <NoGpsState />}`. Outer wrapper attrs: `role="region" aria-label="Trip route map" tabIndex={0} className="relative z-20 ..."` (combine with the responsive position classes above).

    Export named `ViewerMap` (so dynamic import `() => import('@/components/viewer/ViewerMap')` resolves the default-or-named consistently). If using `export default function ViewerMap(...)`, also export the `ChapterCoord` type as a named export for Plan 04-03's RSC.

    Reduced motion: do NOT gate `flyTo` on `useReducedMotion`. The marker pulse animation (UI-SPEC says CSS scale 1→1.3→1, 800ms on the active marker) is OPTIONAL polish — if implementing, gate on `useReducedMotion` via a CSS class swap. If skipping the pulse to keep this task scope tight, document the omission in the SUMMARY as a deferred polish item (UI-SPEC permits this — the marker pulse is "subtle"; the primary functional spec is the static 8px amber dot + flyTo).
